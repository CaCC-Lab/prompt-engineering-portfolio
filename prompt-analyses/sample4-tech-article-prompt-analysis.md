# プロンプト構成意図：GitHub OSS技術解説・実践記事生成

## 🎯 目的
- OSS初心者〜中級者が実際に導入に踏み出せる詳細な技術解説記事の作成
- GitHubプロジェクトのアーキテクチャから実践例まで体系的に解説するコンテンツ提供
- 技術情報と実践体験を融合させた信頼性の高い導入支援記事の効率的生成
- 視覚的要素（図解）と実装手順の詳細化による読者の理解促進

## 🔣 入力
- GitHubリポジトリのURL、またはOSSプロジェクト名（必須）
- 必要に応じて詳細化したい特定セクションの指定（例：「導入支援を厚めに」）（任意）
- 特定の利用シナリオや応用例への言及要望（任意）
- 技術レベルや目的に応じた説明の深さ調整（任意）

## 🏁 出力目標
- キャッチーかつSEO最適化されたタイトルを含む完全なMarkdown形式の技術記事
- Mermaid.js記法によるアーキテクチャ図を含む視覚的な説明
- 段階的な導入手順とトラブルシューティングガイド
- 実際の導入体験レポートを含む独自性のある内容
- メタディスクリプションとアイキャッチ画像プロンプトを含む公開準備完了状態

## 🧠 設計の工夫
### 1. 段階的理解を促す論理的記事構造
- 「概要把握→技術理解→実践支援→体験共有→発展応用→参考情報」という流れ
- セクション間の連続性を重視し、読者の理解度が徐々に深まる構成
- 特に実践レポートセクションを中心に据え、理論と実践を結びつける設計

### 2. 視覚的理解促進機能
- Mermaid.js記法による構成図の自動生成指示
- コンポーネント間の関係性を視覚化する図解の重視
- アイキャッチ画像プロンプトの詳細な指定（構図・色調・雰囲気など）

### 3. 実用性を高める実践的要素
- 番号付き手順による明確なセットアップガイド
- コードブロックの言語指定による可読性向上
- よくあるエラーと対策の具体的提示
- 実際の導入環境・手順・成功体験・課題の詳述

### 4. 読者エンゲージメントと信頼性の構築
- 「自動生成と加筆に関する注記」による透明性確保
- ライセンスや出典情報の明示による信頼性担保
- 筆者視点からの考察による共感形成
- 応援メッセージによる読者の行動喚起

### 5. 技術文書としての品質確保
- Markdown記法の厳格な指定（見出し、コードブロック、表形式など）
- 禁止要素（絵文字、SNSスコアなど）の明確化
- 参考リソースやライセンス情報の体系的提示
- メタディスクリプションの文字数と内容指定

## 🔁 改善プロセス
1. **初期課題の発見**：
   - 技術解説が抽象的で実装に結びつかない問題
   - 図解不足による理解困難
   - ユーザー体験の欠如による信頼性不足

2. **プロンプト改良**：
   - 「実際に導入してみたレポート」セクションの追加と詳細化
   - Mermaid.js記法による図解生成の明示的指示
   - セットアップ手順の番号付きリスト＋コードブロック形式の指定

3. **出力検証と調整**：
   - 複数のOSSプロジェクトでテスト実施
   - セクション間バランスの調整（特に実践支援部分の強化）
   - エラー対策セクションの拡充

4. **実用強化**：
   - 想定指示と出力例の表を追加し対応の柔軟性を向上
   - 最終ルールによる品質チェックポイントの明確化
   - アイキャッチ画像プロンプト生成機能の追加

```

- **絵文字・記号・SNSスコア（+5など）は禁止**
- アーキテクチャ図は**Mermaid.js記法**で生成
