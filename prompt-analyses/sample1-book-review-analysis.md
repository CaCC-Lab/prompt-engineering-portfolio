# プロンプト構成意図：書籍紹介ブログ記事生成

## 🎯 目的
- 書籍紹介ブログのための「コピー＆ペーストで公開可能」な完成度の高い記事を生成
- 読者が「この本を読むべきか」を判断できる、構造化された共感性のあるレビュー記事の提供
- AIを活用しながらも、筆者の専門性・人間性を記事に反映させる仕組みの構築
- ブログ運営における記事作成の効率化と品質の安定化

## 🔣 入力
- 書籍タイトル（必須）
- 必要に応じて記事の焦点や特に言及してほしいテーマの指定（任意）
- 記事の範囲を限定する指示（例：「タグもメタも含めて」「画像も一緒に」など）

## 🏁 出力目標
- Web公開直前の状態の完全なブログ記事（Markdown形式）
- 書籍の要点、著者情報、評判、関連書籍、購入導線、SEO対策をすべて含む
- 特に「書き手の視点」セクションでは筆者の専門性と価値観を反映
- アイキャッチ画像用のプロンプト、SEO対応タグ、メタディスクリプションを含む
- すべての要素が「構造・表記・品質」において整えられた状態

## 🧠 設計の工夫
### 1. AIの役割の明確化
- 冒頭と末尾で「書籍紹介専門GPT」「構造化された読書支援AI」と役割を定義
- 専門性と目的意識をプロンプト全体で一貫させることで、出力の質を安定化

### 2. 構造化された13セクション制約
- AIの創造性を活かしつつ、品質を担保するための詳細な構成指定
- 各セクションの目的・フォーマット・内容要件を具体的に明示
- Markdown形式の厳格な指定（見出しレベル、リスト形式、表形式など）

### 3. パーソナライズ設計
- 「書き手の視点」セクションで筆者のプロフィールと関心事を詳細提供
- 「異分野融合の実践者」としての独自視点を反映させる明示的指示
- 「記事最大のオリジナリティ」と強調し、AIの注意を喚起

### 4. 品質管理機構
- 禁止事項（絵文字、SNSスコア、装飾記号など）の明確化
- 最終確認ルールでのチェックポイント提示
- 「AIによる草稿→筆者による加筆修正」という透明性確保の注記指定

### 5. シナリオ対応設計
- 想定される指示バリエーションと対応方法の具体例提示
- 柔軟性を持たせながらも一貫性を保つための参照ポイント設定

## 🔁 改善プロセス
1. **初期版の課題発見**：
   - 書籍情報の正確性不足（出版年やISBNの誤り発生）
   - 「書き手の視点」セクションが一般的過ぎる問題
   - タグ・メタ情報の欠如によるSEO最適化不足

2. **プロンプト改良**：
   - Web検索指示の追加と信頼性確認指示の強化
   - 筆者プロフィール情報を詳細化し、「異分野融合」の視点強調
   - タグ分類を体系化（テーマ/技術/読者層/著者別）

3. **出力検証と微調整**：
   - 実際の書籍10冊でテスト実施、出力の一貫性を確認
   - Markdown形式での出力エラー（特に表形式）を修正
   - 「関連図書」セクションの関連性強化のための指示追加

4. **実用化改良**：
   - 想定指示パターンと対応例の追加（部分出力対応）
   - 禁止事項と確認ルールの明確化
   - アイキャッチ画像プロンプト指定の具体化（イラスト前提、余白設計）
